# Decisions and trade-offs

A running log. One line per decision, written when the decision is made, not reconstructed
afterwards. Format: **choice** — alternative considered — why.

## Phase 1 — scaffold

| #    | Choice                                                                                 | Alternative considered                                        | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1  | Hand-write the scaffold                                                                | `create-next-app`                                             | The generator ships a landing page, its own CSS, an SVG set and a boilerplate README, all of which would be deleted on the first commit. The brief's standing rule is no dead code in the final tree; the cheapest way to honour that is not to generate it                                                                                                                                                                                                                                        |
| 1.2  | `--spacing: 4px` as the entire spacing scale                                           | Per-step spacing tokens (`--space-1…8`)                       | Pass B's grid is uniform, so one declaration generates it. Every layout constant in the frames then lands on a plain utility — status bar `h-12` (48), banner `h-13` (52), queue `w-108` (432), row `h-10` (40) — which means **zero arbitrary values for layout**, verified in the browser against the running container                                                                                                                                                                          |
| 1.3  | Motion durations as `:root` custom properties, not `@theme` keys                       | Tailwind's `duration-180` bare values                         | One `prefers-reduced-motion` block retargets all three at once, so no component ever branches on the preference in JavaScript. Transforms are dropped separately with the `motion-safe:` variant — the declarative half of the same rule                                                                                                                                                                                                                                                           |
| 1.4  | **Adherence selectors moved to ESLint**; oxlint kept for its fast rule set             | Leave them in `.oxlintrc.json` as the design shipped them     | **oxlint does not implement `no-restricted-syntax`** — verified against 0.15.15, which does not list the rule, so all three adherence rules were silent no-ops: a probe containing `p-[13px]`, `text-[#1a1d21]` and a bad `font-family` linted completely clean. Under ESLint all three fire. Both linters run in `pnpm lint`, so adherence is enforced exactly as the brief requires; only the engine changed. A lint that cannot fail is worse than no lint, because it reads as a passing check |
| 1.5  | Drop `viewport.themeColor`                                                             | Keep it with an eslint-disable                                | The adherence lint caught it on its first real run: it needs a literal hex, which would duplicate `--color-ground` outside the token layer. It only tints mobile browser chrome, which a 1440px+ control-room position never renders. Deleting it keeps the codebase at **zero lint exceptions**, which is a stronger position than one justified suppression                                                                                                                                      |
| 1.6  | Self-host both fonts via `next/font`                                                   | `<link>` to Google Fonts, as the design documents do          | The exported design frames need the network for their fonts; the application must not. A control-room machine can be air-gapped. Build-time download, runtime self-hosted                                                                                                                                                                                                                                                                                                                          |
| 1.7  | `127.0.0.1` in both healthchecks, not `localhost`                                      | The brief's snippet as written                                | **The brief's Dockerfile has a latent bug.** The image's `/etc/hosts` maps `localhost` to both `127.0.0.1` and `::1`; busybox wget tries `::1` first; Next's standalone server binds IPv4 only. The container reported `unhealthy` for four straight probes while serving 200s perfectly. Phase 3's `detector-sim` waits on `depends_on: service_healthy`, so left unfixed this would have deadlocked the compose stack permanently                                                                |
| 1.8  | Compose ships the dashboard alone in phase 1                                           | Include `detector-sim` now, as the brief's compose file shows | Its build context `./services/detector-sim` does not exist yet and it POSTs to an ingest route that lands in phase 3. Including it would produce a compose file that cannot come up — defeating the phase-1 gate, which is to _prove_ `docker compose up` works before any feature is written. It arrives in phase 3 with the route it talks to                                                                                                                                                    |
| 1.9  | `/dev/*` rewritten to 404 in production via `next.config.ts`                           | A `NODE_ENV` guard inside the page                            | The brief requires the state-matrix route be excluded from the production build. A rewrite excludes it at the routing layer rather than shipping the component and hiding it. Verified against the running container: `/dev/states` returns 404 in production                                                                                                                                                                                                                                      |
| 1.10 | TypeScript strict **plus** `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` | Plain `strict: true`                                          | The event store is indexed by id and the schema has six optional fields (`dispatch`, `dismissal`, `seenBefore`, …). These two flags are where the real bugs in that shape live                                                                                                                                                                                                                                                                                                                     |

## Phase 2 — design system layer

| #    | Choice                                                                 | Alternative considered                                          | Why                                                                                                                                                                                                                                                                                                                                    |
| ---- | ---------------------------------------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1  | All five priority cues in one `PRIORITY` map in `src/lib/priority.ts`  | Per-component styling                                           | Colour, border weight, shape, glyph and label are one fact about severity. Holding them in one record means a queue row, a detail chip and a status-bar count cannot drift apart — and the whole redundancy exists for the colour-blind operator on a badly calibrated monitor that Pass B names                                       |
| 2.2  | Priority strip is a sibling element, not a `border-left`               | `border-l-4` / `border-l-3` etc.                                | The strip widths are 1–4px, which come off the 4px scale as `w-0.25`…`w-1`. As border widths they would be arbitrary values. (Verified in the browser: v4 does support bare `border-l-3`, so this was a choice rather than a workaround)                                                                                               |
| 2.3  | Snap type **by role**, not by nearest number                           | Nearest-number rounding                                         | Pass B assigns each scale step a job. The facts panel's 13px mono goes to the 12px step because that step is defined as "timestamps, confidence %, latency" — exactly what the panel holds. Nearest-number would have sent it to 14px, the live-age step, which is a different job                                                     |
| 2.4  | Font weight is **not** baked into the `--text-*` tokens                | `--text-caption--font-weight: 500`                              | Pass C varies weight independently of size at nearly every size — the same row is 500 read and 600 unread. A default weight on the token would make every override depend on utility source order rather than on the class you wrote                                                                                                   |
| 2.5  | Glyph carries screen-reader text unless a visible label sits beside it | Mark every glyph `aria-hidden`                                  | In the queue row the glyph is the _only_ priority signal — there is no visible text label. "Never colour alone" has to hold for assistive technology too, or the row conveys severity to sighted users only                                                                                                                            |
| 2.6  | Hover and focus are **inset** rings                                    | Outline, or a background change                                 | Both cost zero layout, so the row cannot move under the cursor. And per the frames: hover adds no colour at all (colour stays exclusively a priority signal) and focus is neutral white, never the priority colour (focus can never be misread as severity)                                                                            |
| 2.7  | `next/image` with `unoptimized` for snapshots                          | Plain `<img>` with a lint suppression; or the default optimiser | Avoids a lint exception _and_ the optimiser hop. Every queued snapshot is warmed on ingest so opening a detail never shows a spinner — routing the request through the optimiser would defeat the warm cache on the single biggest perceived-speed win in the build                                                                    |
| 2.8  | Camera-failure icon drawn as inline SVG                                | Rotated rule assembled from utilities                           | The strike-through needs a 28° angle, and `-rotate-28` generates nothing in v4 (verified). An icon is the right primitive for an icon, rather than inventing an off-scale rotation utility                                                                                                                                             |
| 2.9  | `NearbyCameras` positions pins by **actual mile marker**               | Evenly spaced, as the frame draws them                          | The frame's three cameras happen to be evenly spaced (41.0 / 42.3 / 43.6), so this renders identically to the drawing — but it stays correct when they are not, which is what a mile-marker schematic is for                                                                                                                           |
| 2.10 | Scoped lint exemption for `src/app/dev/**` prose                       | Reword the design's captions                                    | The state matrix quotes Pass C's captions verbatim — "2px inset", "20px strip", "52px" — because being diffable against the frames is the point of the page. A regex over string literals cannot tell a style value from prose describing one. Narrowed to one development-only route; application code keeps both rules in full force |
| 2.11 | Presentational `DismissReasonMenu`, Radix wrapper deferred to phase 4  | Build the Radix modal now                                       | Pass C draws the trigger as "Dismiss, not real ▾" — a disclosure caret, not the modal the brief describes. A Radix menu satisfies both the design's affordance and the brief's focus-trap requirement, and splitting presentation from behaviour means phase 4 wraps this rather than rewriting it                                     |

## Phase 3 — data and transport

| #    | Choice                                                                     | Alternative considered                                  | Why                                                                                                                                                                                                                                                                                                                                                                                   |
| ---- | -------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1  | **Priority is derived server-side, in the ingest route**                   | Trust the `priority` the detector posts                 | A detector that sets its own priority makes the triage rules unauditable — you could no longer answer "why is this critical?" from the code. The ingest schema omits priority, its reason, status and `receivedAt` entirely, so the wire cannot carry them                                                                                                                            |
| 3.2  | Bias the generator's **inputs**, not its output                            | Pick a priority directly at the chosen 60/30/10 mix     | Weighting event type and lane position and letting `derivePriority` run means every generated event's priority is produced by the same rules as a real one. Weighting the output would make the demo a lie about the logic it is demonstrating                                                                                                                                        |
| 3.3  | Fill the three cells the brief leaves unspecified by **asymmetry of cost** | Pick a default and move on                              | An unconfirmed lane for a pedestrian is treated as a live lane (being wrong is fatal); a stopped vehicle sits between its two outcomes at high; debris and congestion do not escalate at all, because neither has an unrecoverable outcome and escalating them manufactures the alert fatigue Pass A names as a failure mode. Each is unit-tested with the reasoning in the test name |
| 3.4  | `formatAge` hand-rolled, not `formatDistanceToNowStrict`                   | date-fns, as the stack table specifies                  | "3 minutes ago" loses the precision an operator triages on, and its width changes with the wording — the exact jitter tabular figures exist to prevent. date-fns stays for date arithmetic elsewhere                                                                                                                                                                                  |
| 3.5  | A small **ring buffer** on the server, replayed on connect                 | Send only live events                                   | A reconnect that silently drops whatever happened during the gap is the one failure a monitoring tool cannot have. `Last-Event-ID` gives the delta; a fresh load gets the current queue                                                                                                                                                                                               |
| 3.6  | A **fresh load gets a snapshot**, a reconnect gets a delta                 | Treat both as "replay after nothing"                    | Caught by running it: replaying after a null id correctly returns zero events and incorrectly shows an operator an empty queue while incidents are live. Opening the dashboard has to show the shift as it stands                                                                                                                                                                     |
| 3.7  | `useShallow` on the two collection selectors                               | Default reference equality                              | Zustand v5 compares by reference, so selectors that build a fresh array or object would report a change on every store update — including the once-a-second tick — and React would warn the snapshot is not cached. Choosing a store over Context only pays off if this is enforced                                                                                                   |
| 3.8  | One shared interval in the store                                           | One timer per row                                       | A dozen rows means a dozen timers drifting against each other, each scheduling its own render. One store field bumped once a second means one render pass and every counter showing the same second                                                                                                                                                                                   |
| 3.9  | Events validated with Zod **on arrival at the client**                     | Trust our own route handler                             | Belt-and-braces, but a malformed event reaching the store corrupts a queue someone is making dispatch decisions from. Failing loudly at the boundary is far cheaper than debugging that                                                                                                                                                                                               |
| 3.10 | `detector-sim` is a **separate container** posting over HTTP               | Run the simulator in-process behind `SIM_MODE=internal` | The boundary the brief describes — between the detection system and the people — becomes visible in `docker compose ps` rather than being a function call buried in a route. In-process is still supported and is what `pnpm dev` uses                                                                                                                                                |
| 3.11 | Snapshots are **committed SVG stills**, one per event type                 | Hotlink stock photography                               | A reviewer may be offline. SVG also keeps them a few KB each and lets them be drawn in the Pass B surface values, so a still sits in the evidence well without a seam                                                                                                                                                                                                                 |
| 3.12 | Vitest pinned to **3.x**; no React plugin, no jsdom, no RTL                | Vitest 4 with the full DOM stack                        | Vitest 4 pulls in rolldown, whose native binding fails to install on Windows — a reviewer cloning this would hit the same wall. And the brief scopes tests to "the priority logic and the store, not the pixels", both of which are plain modules; a DOM and a JSX transform would be unused dependencies                                                                             |

## Phase 4 — queue and detail

| #    | Choice                                                                      | Alternative considered               | Why                                                                                                                                                                                                                                                                                                                                                          |
| ---- | --------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 4.1  | **`set((state) => …)` everywhere in the store**                             | `get()` then `set(computed)`         | Not style — a correctness fix. Read-modify-write is a race: two events delivered in the same tick both read the same array and the second write discards the first, which is exactly what a reconnect replay and React's strict double-mount produce. Measured against the running app: **five of twenty-one events survived**. Covered by a regression test |
| 4.2  | One `selectedId`, no separate focused row                                   | Track focus and selection separately | Pass A's model is "↑↓ moves and previews" — the row under the cursor _is_ the one in the detail pane. A second piece of state would only exist to be kept in sync with the first                                                                                                                                                                             |
| 4.3  | Selection **clamps** at both ends                                           | Wrap around                          | Wrapping from the last row back to the top is disorienting when the list is also growing underneath you. A queue is not a carousel                                                                                                                                                                                                                           |
| 4.4  | The status bar's open counts **are** the filter control                     | A separate filter bar                | The brief needs 1–4 to act on something visible; Pass C draws no filter UI. Making the existing counts interactive is the smallest honest extension — the alternative was inventing a component the design never drew. Excluded priorities dim rather than disappear, so the row keeps its shape and the numbers stay where the eye expects them             |
| 4.5  | Undo restores the **prior status**, not `new`                               | Reset to `new`                       | Dismissing an acknowledged incident and undoing must give the operator their incident back — still locked to them — rather than release it for another position to claim. `dismissal.previousStatus` exists for exactly this                                                                                                                                 |
| 4.6  | Leaving rows are derived from the shared tick                               | A `setTimeout` per dismissal         | The 8-second undo window and the 3-second resolved fade are computed from `dismissal.at` against the tick that already exists. Timers per row would drift, leak on unmount, and duplicate the clock the store already owns                                                                                                                                   |
| 4.7  | Dispatch confirms; nothing else does                                        | Confirm every action, or none        | A dispatch moves people and costs money; acknowledging and dismissing are both recoverable (undo, and the audit trail). The confirm button takes focus on open so `D` then `Enter` completes it — a four-second modal on a critical costs more than the mis-dispatches it prevents                                                                           |
| 4.8  | Radix **menu** for dismissal, not a modal                                   | The brief's modal                    | Pass C draws the trigger with a disclosure caret. Radix's menu still supplies the focus trap, roving focus, type-ahead and `Esc`, so the design's lighter affordance costs nothing in accessibility                                                                                                                                                          |
| 4.9  | The `?` overlay renders from the **same table** the handler dispatches from | Hand-written help content            | A help screen maintained separately from the bindings drifts from them. Here a binding cannot be published and missing, or working and undocumented                                                                                                                                                                                                          |
| 4.10 | Ship the `?` overlay even though the design has none                        | Omit it, for fidelity                | Pass C has no help affordance because its operator is trained. A take-home reviewer is not that operator. Built entirely from the design's tokens so it does not read as a bolt-on — recorded here as a deliberate addition rather than an oversight                                                                                                         |
| 4.11 | Roving tabindex on the queue                                                | Every row tabbable                   | Tab should move _past_ the queue, not through fifteen incidents. Moving within it is ↑↓ — Pass A's "one keyboard axis, no mode"                                                                                                                                                                                                                              |
| 4.12 | Demo affordances behind explicit body shapes                                | Reuse the ingest route loosely       | `{}` means "make something up" and `{ preset: 'critical' }` forces a wrong-way driver, so a real observation can never accidentally take the demo path                                                                                                                                                                                                       |

### Stack rejections, recorded up front

Required by the brief's §3, and each one holds after reading the design.

| Rejected                    | Why                                                                                                                                                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WebSockets / socket.io      | Needs a custom server and bidirectional plumbing we never use. Every message flows detector → operator; SSE is one-way by construction, auto-reconnects, and works behind Docker with a plain route handler |
| shadcn/ui                   | Ships its own opinionated token layer that would fight Pass B's. Radix unstyled gives the same accessibility primitives with no competing values                                                            |
| A real database             | This is a front-end evaluation. State lives in the store; the audit trail is per-session and the README says so                                                                                             |
| Redux Toolkit               | Ceremony without benefit at this size. One high-frequency slice needs a subscribable store, not middleware and a devtools protocol                                                                          |
| CSS-in-JS                   | Runtime cost on a surface that re-renders every second by design (the shared age-counter tick)                                                                                                              |
| Context for the event store | Would re-render every subscriber on every tick. Zustand's selector subscriptions keep a one-second tick from repainting the world                                                                           |
